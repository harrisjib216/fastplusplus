## Verdict

The README table is one wall-clock run per interpreter CLI of recursive fib(35), process start included, generated by d5/tengobench in May 2020 on unstated hardware: Tengo 2,315 ms vs go-lua 4,028 ms, GopherLua 4,409 ms and goja 5,194 ms, with native Lua faster at 756 ms. Third-party reruns agree on the ordering: ozanh/ugobenchfib (Apple M1 Parallels VM, Ubuntu 20.04, Go 1.18, tengo v2.10.1, May 2022) measured Tengo 2.19 s vs go-lua 2.90 s, GopherLua 3.21 s, goja 3.33 s and native Lua 1.00 s, and mna/bench_go_scripting (Lenovo T460, August 2024) measured fib at Tengo 3.04 s vs Risor 4.89 s.

## Use it when

- A Go service that needs user-editable rules, transforms or state machines in pure Go (no cgo), and where you can choose the script language.
- Call-heavy CPU-bound scripts (recursion, small functions, loops): in four third-party fib(35) runs (ozanh/ugobenchfib, 2020-2022) Tengo beat go-lua by 1.33-1.75x, GopherLua by 1.47-1.88x and goja by 1.52-2.05x (derived from page data).
- Running untrusted scripts: no modules are importable unless allowed with SetImports, file imports are off by default, SetMaxAllocs caps object allocations and RunContext cancels on a context.
- Compile once, run many times: Compiled.Set/Get change and read globals between runs and Compiled.Clone gives copies safe for concurrent execution.

## Skip it when

- Users must write Lua, JavaScript or Python, or you need those ecosystems' libraries: use GopherLua or goja instead.
- You need C-Lua-level speed: native Lua ran fib(35) 3.1x faster in the README (756 ms vs 2,315 ms) and 2.2x faster in ugobenchfib (1.00 s vs 2.19 s); with cgo allowed, embed Lua, LuaJIT or Luau.
- Evaluating a tiny expression per request: every Run builds a new VM with fixed arrays of about 80 KB (2,048-slot stack plus 1,024 frames, computed from vm.go), and issue #412 proposing a pool is open; a dedicated expression engine such as Expr fits better.
- Non-tail recursion deeper than 1,024 frames, which fails with ErrStackOverflow (only direct self tail calls are flattened).
- Projects that need an actively answered upstream: commits are sporadic (a few community fixes per year) and issue #464 'Is this project still alive?' (June 2025) shows no maintainer reply.

## How it is fast

Source is compiled once to compact bytecode (opcodes with 1-2 byte operands, a constants pool, globals and locals addressed by index) with dead code after returns removed (optimizeFunc), and the VM runs it in one switch loop over a fixed 2,048-slot stack and 1,024-entry frame array allocated with the VM. Direct self-recursive tail calls reuse the current frame instead of pushing a new one (vm.go). Values are Go interface Objects and every integer arithmetic result is a freshly allocated \*Int (objects.go), so arithmetic-heavy code is bound by Go's allocator and GC, which is why native C Lua stays 2-3x ahead.

## Compared with alternatives

Pick Tengo over GopherLua and goja when you control the script language and want the fastest pure-Go general-purpose interpreter for call-heavy code (about 1.5-1.9x over GopherLua and 1.5-2.2x over goja on fib(35)); pick GopherLua or goja when scripts must be Lua or JavaScript, Expr for single expressions evaluated at high rates, and note that the Tengo-derived uGO ran fib(35) about 1.1x faster than Tengo in its author's 2022 runs.

## Gotchas

- Harness flaw: tengobench cmd/bench/main.go times a single os/exec run per interpreter including process start and discards the exit error (`_ = cmd.Run()`), so a crashing interpreter would show a tiny time; outputs are never checked. The README table dates from May 2020 (tengo v2.1.2, competitors pinned to 2019-2020 commits) and the native Go row runs a compiled binary that does not read the source file. The uGO fork (ozanh/ugobenchfib) reuses the same single-run, error-ignoring harness.
- The margin depends on the Go compiler: on the same Apple M1 VM, ugobenchfib measured Tengo's lead over go-lua at 1.72x with Go 1.17 and 1.33x with Go 1.18 (derived from page data), so the README's 1.7x over go-lua is not a stable figure.
- Every integer arithmetic result allocates a new \*Int, and each OpBinaryOp counts against SetMaxAllocs, so allocation caps trip on plain arithmetic loops, not only on data-structure creation.
- Recent correctness fixes: `int == float` always returned false until #477 (April 2026), dead-code elimination produced 'invalid jump position' errors (#376, #431), and a 10,000-key map panicked (#402); fmt.println writes straight to process stdout with no per-script capture (issue #342, open), so replace the fmt module (ReplaceBuiltinModule) to isolate output.

## Known shortcomings

- tengobench numbers last refreshed May 2020, one run with cmd.Run() errors ignored and no hardware; native Lua (756 ms) and Python 2 (1,907 ms) beat Tengo (2,315 ms), and the fibt claim was cherry-picked (a 3-way tie at 3 ms). Go; filed under embedded-scripting.
- Enricher: every integer arithmetic result allocates a new \*Int and counts against SetMaxAllocs; maintenance is sporadic (issue #464 has no maintainer reply, the int == float bug was fixed only in 2026 in #477). Independent ozanh/ugobenchfib rerun (M1 VM, Go 1.18): Tengo 2.19 s vs go-lua 2.90 s, GopherLua 3.21 s, goja 3.33 s, native Lua 1.00 s, with Tengo's lead over go-lua dropping from 1.72x to 1.33x between Go 1.17 and 1.18; mna/bench_go_scripting (2024): Tengo 3.04 s vs Risor 4.89 s.

## Maintenance

Sporadically maintained (last commit 2026-10-03 after a year-long gap in 2024-2025; maintainer silent on issue #464), MIT and dependency-free pure Go, so easy to vendor; the ugobenchfib reruns are an independent measurement with hardware and Go version stated, which could support tier B for the comparison against other Go-hosted interpreters, though not against C Lua.
