## Verdict

ahaoboy/js-engine-benchmark's daily GitHub Actions run (results dated 2026-10-05) runs the eight v8-v7 tests once per engine on ubuntu-latest and macos-latest arm64 runners (CPU not stated): LibJS, from Ladybird's own CI build (Distribution preset, clang), scores 691 vs 489 for Duktape 2.99.99 built at -Os on Ubuntu (about 1.4x) and 1169 vs 905 on macOS arm64 (about 1.3x), while QuickJS 2026.06.04 scores 1217 and 1761.

## Use it when

- You need a BSD-2-Clause engine aiming at full spec conformance (per an April 2026 newsletter snippet, 97.8% of 53,207 imported test262 subtests) and can live with interpreter-only speed.
- Your code already builds inside the Ladybird or SerenityOS library stack (AK, LibGC, LibCore), so the dependency cost is already paid.
- Object-heavy or numeric scripts on x86-64 or aarch64 Linux/macOS where you would otherwise use a size-optimised Duktape: 1.4x the Duktape score on Ubuntu, 1.3x on macOS arm64, and ahead on 7 of 8 v8-v7 tests (Crypto 1025 vs 783).
- Studying a modern DSL-generated assembly interpreter (Flap) as a design reference.

## Skip it when

- Size-constrained embedding: the js binary is 43.8 MB on Ubuntu and 40.2 MB on macOS, against about 1 MB for QuickJS and 370 KB for Duktape (Score/MB 15 vs 1190 and 1352).
- CPUs other than x86-64 and aarch64: LibJS/CMakeLists.txt stops with FATAL_ERROR because the generated assembly interpreter is the only interpreter (no portable C++ fallback any more).
- RegExp-heavy scripts: LibRegex scores 66 vs Duktape 129 and QuickJS 398 on Ubuntu (114 vs 244 and 502 on macOS).
- When throughput matters more than conformance: QuickJS (1217 / 1761), Hermes 0.12.0 (1530 / 1233) and PrimJS (737 / 1694) all outscore it on Ubuntu / macOS in the same suite.
- When you need a stable, versioned embedding API: no standalone release, the C++ API is internal and changes with master, and the browser itself is labelled pre-alpha.

## How it is fast

Since March 2026 (PR #8299, 'AsmInt') the interpreter handlers are written in Flap, a typed DSL (Interpreter/interpreter.flap) that the Rust tool flapc lowers through SSA and register allocation into x86-64 or aarch64 assembly at build time; the bytecode PC and register-file pointer stay in machine registers and dispatch goes through a jump table. Values are NaN-boxed, and property access uses shape-keyed inline caches on the fast path, with slow paths in C++ (SlowPaths.cpp). PR #8299 reports 1.13-1.45x aggregate over the earlier C++ computed-goto interpreter (Kraken, Octane, JetStream; first-party). The LibJS tree has no JavaScript JIT tier.

## Compared with alternatives

Choose LibJS over QuickJS or njs only when spec conformance, the BSD-2 licence and the Ladybird code base matter more than binary size, portability and speed; QuickJS is faster in this same suite at about 1/40 of the size and embeds as a small C library, and Duktape remains smaller with a stable C API.

## Gotchas

- The baseline is weak: Duktape 2.99.99 is unreleased master built with Duktape's default Makefile (-Os -fomit-frame-pointer), while LibJS uses Ladybird's Distribution preset with clang; against release-grade small engines (QuickJS, PrimJS, Hermes) LibJS loses.
- Rankings swing by platform in this suite: LibJS beats QuickJS-NG 0.17.0 on Ubuntu (691 vs 647) but not on macOS (1169 vs 1660), and njs 0.9.2 beats it on Ubuntu (721) but not on macOS (950); one run per engine per day on shared runners, so treat gaps under about 10% as noise.
- The suite's wall-clock column is longer for LibJS than for Duktape despite the higher score (79 s vs 70 s Ubuntu, 53 s vs 46 s macOS); the score covers only the timed benchmark loops, not process startup or teardown.
- The harness pulls the latest successful master CI artifact daily and leaves the version cell blank (getVersion returns '' for ladybird), so a given score cannot be tied to a commit; Flap interpreter assertions are compiled into every build type (--enable-assertions), so they are included in the numbers.

## Known shortcomings

- LibJS beats only a Duktape built -Os from master on ahaoboy CI (691 vs 489 on ubuntu, 1169 vs 905 on macOS), loses to QuickJS by 1.5-1.8x and to Duktape on RegExp, with a longer total time (79 vs 70 s); binary from the Ladybird CI Distribution preset (clang) with the runner CPU unstated. Not a standalone embeddable library.
- Enricher: the LibJS interpreter is a Flap DSL compiled to assembly by the Rust flapc (PR #8299, first-party 1.13-1.45x over the old C++ interpreter), x86-64 and aarch64 only, with ICU, Rust and vcpkg dependencies and a 43.8 MB binary. The ahaoboy harness runs each engine once a day with a blank version cell (getVersion returns ''), so the score is not tied to a commit; LibJS beats QuickJS-NG 0.17.0 on Ubuntu (691 vs 647) but not on macOS (1169 vs 1660), njs beats it on Ubuntu (721), and Hermes and PrimJS sit above it on both.

## Caveats and trade-offs

Third-party CI suite with one run per daily snapshot and no runner CPU model. The Duktape baseline is a size-optimized (-Os) build of unreleased master, which handicaps it; LibJS uses Ladybird's Distribution preset. LibJS is slower than Duktape on RegExp (66 vs 129 on Ubuntu, 114 vs 244 on macOS) and faster on the other seven tests (Crypto 1025 vs 783). It beats only Duktape, not QuickJS (1217 Ubuntu, 1761 macOS), among the listed baselines, and the suite's Time(s) row shows LibJS taking longer overall (79 s vs 70 s Ubuntu, 53 s vs 46 s macOS). The suite page leaves LibJS's version cell blank. LibJS ships only inside the Ladybird browser monorepo (no separate release found), so embedding it means pulling in Ladybird's own libraries; no Windows build is benchmarked. Per a search snippet (Ladybird newsletter, page not opened), LibJS runs an assembly bytecode interpreter; the Cranelift JIT in recent builds is for LibWasm.

LibJS lives inside the Ladybird browser tree (inherited from SerenityOS), not packaged as a small standalone embeddable library; the benchmarked executable is 43.8 MB on Ubuntu versus 1 MB for QuickJS. Targets full ECMAScript conformance.

## Maintenance

Very active (66.4k stars, commits daily, last 2026-10-06) and BSD-2-Clause, but LibJS is reachable only as part of a pre-alpha browser monorepo with a heavy build (Clang, vcpkg, Rust), so treat it as a reference design or an option for Ladybird-based projects rather than a drop-in embeddable engine.
