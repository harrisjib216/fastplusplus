# data/

<sub>[fastpp](../README.md)</sub>

Every intermediate record the pipeline produced, kept so each catalog entry can be traced back to the search,
verification and enrichment that made it. The catalog under [`catalog/`](../catalog/README.md) is rendered from
these files; read the exports there (schema in [docs/schema.md](../docs/schema.md)) unless you need the raw trail.

## One directory per wave

| Directory | Domain |
|---|---|
| `wave0-seed` | Seed records for well-known projects that later searches skip (the initial known list) |
| `wave1`, `wave1-phf` | `stdlib-replacements` (wave1-phf: the perfect-hash-function sub-wave) |
| `wave2` | `toolchain-and-build` |
| `wave3` | `parsing-and-text` |
| `wave4` | `serialization-and-formats` |
| `wave5` | `networking-and-servers` |
| `wave6` | `storage-and-data` |
| `wave7` | `crypto-and-hashing` |
| `wave8` | `numerics-and-science` |
| `wave9` | `compression-and-encoding` |
| `wave10` | `media-and-graphics` |
| `wave11` | `runtime-and-systems` |
| `wave12` | `interpreters-and-vms` |
| `wave13` | `assembly-simd-kernels-and-wasm` |
| `wave14` | `other-languages-faster-than-c-cpp-asm` |

A few entries in each wave are filed under another domain by a category override.

Inside a wave directory, in pipeline order:

| Path | Written by | Holds |
|---|---|---|
| `assignments.json` | orchestrator | The wave's search assignments: category × source batch (b1 GitHub C++, b2 papers, b3 GitHub second pass, b4 shootouts, b5 registries, b6 GitHub any language, b7 blogs, b8 Hacker News), plus seed and mining groups. |
| `prompts/` | `render.py`, `seed.py` | One search or seed prompt per assignment. |
| `raw/` | search agents | One JSON array of candidate records per assignment. |
| `merged.json` | `merge.py` | Deduplicated candidates with stable ids. |
| `verify/prompts/`, `verify/raw/batch-NN.json` | `verify.py render`, verifier agents | Verifier prompts and verdicts, three records per batch. |
| `verify/raw/retier-NN.json` | retier checks | Later tier moves and field corrections, applied on top of the verdicts. |
| `verified.json` | `verify.py apply` | Entries that passed verification, with the verifier's notes. |
| `rejected.json` | `verify.py apply` | Candidates rejected for invalid evidence. |
| `enrich/prompts/`, `enrich/raw/<slug>.json` | `enrich.py`, enrichment agents | The write-up for each verified entry. |
| `evidence_for_known.json` | `merge.py` | New evidence found for projects already in the catalog. |
| `leads.md` | orchestrator | Projects enrichers mentioned that were not yet catalogued; the source of seed passes. |

## Shared files

| Path | Holds |
|---|---|
| `decisions.json` | Every keep, duplicate and reject decision, with shortcomings, measurements and override fields (name, category, domain, repo URL, language). Written by `pipeline/add_decisions.py`. |
| `known_list.txt` | Generated by `merge.py`: every catalogued or rejected URL, so searches skip them. |
| `known_seed.txt` | The hand-written seed of the known list. |
| `seeds/` | Seed-list mining: `seeds.json` (projects mined from curated lists such as awesome-cpp and awesome-c), the mining prompts and raw outputs, and `no_evidence/` for projects with no published comparison. |

Archived prompts keep the absolute output paths the agents wrote to; paths from personal machines were rewritten
to `/path/to/fastpp`.
